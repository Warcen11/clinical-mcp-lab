# Clinical MCP Lab — Практическое задание 2

Учебное веб-приложение с **тремя реальными MCP-транспортами**, динамическими формами из `tools/list` и JSON-RPC инспектором. Реализовано для Python 3.11/3.12, MCP SDK **2.3.x**.

> ⚠️ Только демонстрационные данные. Это не медицинское ПО и не инструмент для диагностики или назначения лечения. Не вводите персональные данные пациентов, особенно во внешний MCP.

## Запуск (Windows PowerShell)

Выполняйте команды **из корня проекта**:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python run.py
```

Откройте `http://127.0.0.1:8501`. После установки зависимостей приложение и SSE-сервер запускаются **одной командой** `python run.py`. Для macOS/Linux: `python3 -m venv .venv && source .venv/bin/activate`, затем те же `pip` и `python run.py`.

### Три источника MCP

| Источник | Реальный транспорт | Запуск | Инструменты |
|---|---|---|---|
| 1. Stdio | `stdin/stdout`, отдельный процесс | `python -m clinical_mcp.stdio.server` (автоматически из UI) | BMI, GCS, Cockcroft–Gault, `list_calculators` |
| 2. Network | `http://127.0.0.1:8000/sse`, JSON-RPC POST на `/messages?session_id=...` | `python -m clinical_mcp.network.server` (автоматически через `run.py`) | 6 шкал: cardio MAP, CHA₂DS₂-VASc, nephro CrCl, critical GCS, qSOFA, BMI |
| 3. Remote | Streamable HTTP, `https://pubmed.caseyjhand.com/mcp` | Публичный сервер стороннего разработчика, требуется интернет | PubMed (список определяется сервером динамически) |

Если внешний сервер недоступен, задайте переменную окружения `CLINICAL_MCP_REMOTE_URL` (полный HTTPS MCP endpoint). Список инструментов не подменяется локальными моками.

### Как пользоваться

1. Выберите источник в боковой панели.
2. Найдите инструмент по русскому или латинскому названию.
3. Введите параметры в форму, построенную **динамически из JSON Schema, полученной по `tools/list`**.
4. Нажмите кнопку вызова: реальный `tools/call` проходит через MCP-клиент и соответствующий транспорт.
5. Раскройте **MCP Packet Inspector** — он фиксирует фактические сообщения SDK на границе транспорта: `initialize`, `notifications/initialized`, `tools/list`, `tools/call` и ответы.

Параметры не заполняются выдуманными «нормальными» значениями. Клиент приводит типы (например, «80,5» → `80.5`) и валидирует допустимые пределы. Отсутствующие измерения требуют явного ввода, а ошибки показаны без падения UI. Это безопаснее для клинического контекста, чем молчаливая подстановка значений.

### Исправление совместимости с MCP SDK 2.x

`ClientSession.list_tools()` теперь принимает `params=PaginatedRequestParams(cursor=...)`,
а не `cursor=...` напрямую. Это исправлено в `clinical_mcp/client/router.py`.
В интерфейсе также разворачиваются вложенные `ExceptionGroup` / `TaskGroup` ошибки.
В `clinical_mcp/client/tracing.py` добавлены асинхронные контекстные менеджеры `ReadTap` и `WriteTap`, необходимые для `JSONRPCDispatcher` MCP SDK 2.3.

### Тесты

```powershell
python -m pytest -q
```

В первую очередь тестируются математические формулы и проверка входных данных. `tests/test_mcp_integration.py` запускает настоящий stdio MCP сервер и проверяет реальный протокол. Для дополнительной проверки SSE самостоятельно запустите `python -m clinical_mcp.network.server` и подключитесь через UI.

### Диагностика ошибки 503 на /sse

```powershell
python diagnose_sse.py
```

В норме выводятся `TCP: порт 8000 принимает соединения`, `HTTP без прокси: 200`
и `Content-Type: text/event-stream`. Скрипт подключается **напрямую** к loopback,
поэтому системный прокси/VPN не может перехватить запрос. Если порт занят,
`run.py` сообщает об этом до запуска интерфейса. В клиентском SSE-подключении
`trust_env=False` действует **только для локального сервера**; удалённый PubMed
по-прежнему может использовать системные настройки сети.

### Запуск компонентов отдельно

```powershell
python -m clinical_mcp.network.server
# Во втором терминале
python -m streamlit run app.py
```

`stdio` сервер вручную запускается без видимого вывода, ожидая JSON-RPC запросов по stdin. **Не использовать `print()` для логирования в stdout** — оно зарезервировано протоколом. Логи идут в stderr.

### IDE Cursor

В `.cursor/mcp.json` есть конфигурация трёх MCP серверов. IDE нужно открыть в корне репозитория и указать Python интерпретатор `.venv` — при необходимости замените `python` на абсолютный путь к `.venv/Scripts/python.exe`. SSE сервер должен уже работать.

### Небольшие улучшения интерфейса (v4)

- В SSE-клиенте используется стандартный пакет `httpx` (исправлена опечатка `httpx2` в v3).
- Необязательные поля формы свёрнуты в блок «Дополнительные параметры». Обязательные параметры остаются видимыми.
- Результаты `pubmed_search_articles` с полем `pmids` отображаются как ссылки на PubMed, а полный ответ сервера остаётся доступен в раскрывающемся блоке. Инспектор JSON-RPC продолжает показывать фактический обмен.

### Особенности MCP 2.x и требования задания

- В SDK v2 класс `FastMCP` переименован в `MCPServer`.
- SSE — legacy-транспорт, оставлен **специально по требованию задания**; новые приложения обычно используют Streamable HTTP.
- Внешняя служба использует Streamable HTTP, что допускается в описании трёх вариантов; это **не подмена обычным REST API**.
- Учебное задание на странице 3 одновременно требует `mcp SDK 2.x`, но на странице 5 предлагает установить `mcp>=1.3.0`; проект следует более конкретному требованию и использует SDK 2.3.x.
- Streamlit кэширует внешние `tools/list` (45 секунд) и вызовы remote `tools/call` (5 минут), ставит таймаут на внешний запрос 12 секунд. SSE переподключается до трёх раз при кратковременных сетевых сбоях.
- *Физиологические умолчания*: не подставляем клинические данные за пациента. Требование «Smart Defaults» выполняем только на уровне явного UI поведения/значений checkbox и контролируемого преобразования типов.
- Клинические калькуляторы — обучающие; Cockcroft–Gault оценивает клиренс креатинина, **не** CKD-EPI eGFR.

### Структура

```text
clinical_mcp/common/calculators.py     Формулы без сетевых вызовов
clinical_mcp/common/catalog.py         Описание методик
clinical_mcp/stdio/server.py           MCP stdio сервер
clinical_mcp/network/server.py         MCP SSE сервер :8000
clinical_mcp/client/router.py          3 независимых клиента MCP
clinical_mcp/client/tracing.py         Перехват реальных пакетов SDK
clinical_mcp/client/validation.py      Проверка JSON Schema аргументов
app.py                                 Streamlit интерфейс
run.py                                 Один запуск UI и SSE-сервера
.cursor/mcp.json                       Конфигурация IDE
```

### Как показать на защите

1. **Stdio:** BMI для 80 кг, 180 см = 24.69, открыть JSON-RPC инспектор.
2. **SSE:** выбрать `critical_gcs`, значения `4,5,6` = 15 баллов, показать URL SSE и JSON-RPC.
3. **Remote:** выбрать PubMed инструмент поиска; ввести англоязычный запрос, например `diabetes`, показать ответ и Inspector. Названия полей будут зависеть от живого `tools/list` внешнего сервера.
4. Преднамеренно очистить обязательное поле или ввести выходящее за диапазон значение — должна появиться понятная ошибка, без падения приложения.
